# CI pipelines

Labs that teach shipping can mock a CI pipeline. This one enables the **CI** tab
(look for the 🚀 tab on the right). A `git push` triggers a run that plays out
GitHub-Actions style — queued → running → per-step → conclusion.

## Push to trigger a run

First, make sure the deploy target from the previous section is **off** (Settings
tab → _Configure a deploy target_) so you can see a failure. Then commit and
push:

```bash
git add .
```

```bash
git commit -m "Add greeting service"
```

```bash
git push
```

The CI tab comes forward automatically and the pipeline runs: **Build** and
**Test** pass, but **Deploy** fails — its outcome isn't hard-coded, it depends on
whether a deploy target is configured (the same control from the last section).

## Fix it without pushing again

There's nothing new to commit, so a second `git push` would be artificial.
Instead:

1. Open **Settings** and turn on **Configure a deploy target**.
2. Go to the **CI** tab and press **Re-run jobs** on the failed run.

The pipeline re-evaluates against the _current_ state and goes green — Deploy now
passes. This "fix the config, re-run" loop mirrors real CI, and it works because
the step's pass/fail is derived from state rather than scripted per push.
