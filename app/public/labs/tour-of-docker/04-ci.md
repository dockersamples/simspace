# Build and sign in CI

The workflows from the previous sections — build, scan, push — really belong in
**CI**, so they run automatically on every change. This lab ships a mock **CI**
tab (in the right-hand pane) that shows workflow runs, just like GitHub Actions.

We'll add a pipeline that **builds** the image, **pushes** it to Docker Hub, and
**signs** it with [cosign](https://github.com/sigstore/cosign) so downstream
policies can verify where it came from.

## Create the workflow

Click **Save** on the block below to write it to
`.github/workflows/build.yml` in the repo:

```yaml save-as=.github/workflows/build.yml
name: Build, Push & Sign

on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build image
        run: docker build -t docker.io/acme/scout-demo:latest .

      - name: Log in to Docker Hub
        run: echo "$DOCKER_PAT" | docker login -u "$DOCKER_USER" --password-stdin
        env:
          DOCKER_USER: ${{ secrets.DOCKER_USER }}
          DOCKER_PAT: ${{ secrets.DOCKER_PAT }}

      - name: Push image
        run: docker push docker.io/acme/scout-demo:latest

      - name: Sign image with cosign
        run: cosign sign --yes docker.io/acme/scout-demo:latest
```

## Commit and push

Stage the workflow, commit it, and push:

```bash terminal-id=host
git add .github/workflows/build.yml
```

```bash terminal-id=host
git commit -m "Add build, push and sign workflow"
```

```bash terminal-id=host
git push
```

Watch the **CI** tab — it comes forward automatically. The pipeline checks out
the code and builds the image, then **fails at _Log in to Docker Hub_**: the
`DOCKER_USER` / `DOCKER_PAT` secrets aren't set, so the push and sign steps are
skipped. Expand the failed run to read the log.

## Configure credentials and re-run

Open the **Settings** tab and turn on **Configure Docker Hub credentials**. This
is the simulated equivalent of adding the `DOCKER_USER` and `DOCKER_PAT` secrets
to the repository.

Nothing changed in the code, so there's nothing new to commit or push. Instead —
just like in GitHub Actions — go back to the **CI** tab and press **Re-run jobs**
on the failed run. A re-run picks up the _current_ configuration, so now that the
secrets are set it can log in.

This time it goes green: the image builds, logs in, **pushes**, and is **signed**
— every step succeeds. Expand the run to see it end to end.

> In a real repo the credentials would live in your CI secrets and `cosign` would
> publish the signature to the registry. Here it's all scripted so you can focus
> on the _shape_ of a build-push-sign pipeline without any infrastructure.
>
