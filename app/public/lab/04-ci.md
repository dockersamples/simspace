# Sign images in CI

Many pipelines don't just build an image — they **sign** it so downstream
policies can verify where it came from. This lab ships a mock **CI** tab (in the
right-hand pane) that shows workflow runs, just like GitHub Actions. Every
`git push` triggers the _Build and Sign_ workflow.

## Push without a signing key

Commit the workflow and push it:

```bash terminal-id=host
git commit -m "Add signing workflow"
```

```bash terminal-id=host
git push
```

Watch the **CI** tab — it comes forward automatically. The pipeline checks out
the code and builds the image, then **fails at the _Sign image_ step**: no
signing key is configured. Expand the failed run to read the condensed log and
the error.

## Configure the key and push again

Open the **Settings** tab and turn on **Configure image signing key**. This is
the simulated equivalent of adding a `cosign` key to the pipeline's secrets.

Now push again:

```bash terminal-id=host
git push
```

This time the run goes green: the image is built, **signed**, and the signature
policy is verified. Expand the run to see every step succeed.

> In a real pipeline the key would live in your CI secrets and `cosign` would
> push the signature to your registry. Here it's all scripted so you can focus
> on the _shape_ of a signing pipeline without any infrastructure.
